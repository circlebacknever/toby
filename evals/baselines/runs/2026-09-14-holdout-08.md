## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from Chase, Monzo, Wise, and ING. Ledgerline matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. It writes rows it cannot match to `review.csv` for a person to check. It reads the accounting system through an API token with read-only scope.

#### Install

Ledgerline needs Python 3.11 or later. Install it with `brew install ledgerline`.

#### Add a bank format

To add a bank, write a parser in `parsers/<bank>.py`. Parsers must not make network calls. CI checks this rule and fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are in a single Redis node. Its memory use is at 71 percent and grows by about 3 percentage points a week. At that rate, the node reaches full memory in about 10 weeks.

#### Option A, a second Redis node

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, where they took 2 ms at p95 in staging. The team has not run sharded Redis before.

#### Option B, sessions in Postgres

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres, compared with 2 ms on Redis. The session read runs once per page load, so every page load would include one read that was 7 ms slower at p95 in staging.

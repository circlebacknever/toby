## 1

### Relay

Relay is a platform for building multi-agent apps. Users give agents instructions, and the agents read documents, call tools, and wait for a person to approve anything destructive. Relay consists of two packages. The `@relay/ui` package contains shared generative UI components. The `@relay/agents` package contains the runtime, which handles tool calling, memory, and pauses for human approval before a destructive action. Each model provider is an engine, and engines are swappable.

#### Install

Relay requires Node 20 or later, and npm installs both packages with one command.

```sh
npm install @relay/ui @relay/agents
```

#### Writing a plugin

A new agent in Relay is a plugin. A plugin consists of a JSON manifest and handler functions, and Relay compiles the manifest at build time. A plugin never imports an engine directly.

## 3

### Adding a plugin

A plugin is a directory, `plugins/<name>/`, that contains `manifest.json` and `handlers.ts`.

1. Create `plugins/<name>/` with a `manifest.json` file and a `handlers.ts` file.
2. In each handler, use the engine from `ctx.engine`.
3. Do not import from `engines/` in any plugin file. The build fails the plugin with `E_ENGINE_IMPORT`.
4. Run `npm run plugins:check` before you open a PR. The command validates every manifest.

The build rejects engine imports because they broke every plugin the last time a provider changed its SDK.

**Consequence.** When `processEvent` throws, the handler logs a warning and still returns 200, so the payment provider stops retrying and never resends that event (`api/webhooks.ts:41`).

**Fires when.** The payment provider posts a webhook and `processEvent(req.body)` throws for any reason, because every error goes to the `catch` block.

**Guard.** The `catch` block is the only check, and it calls `logger.warn(err)` and then lets `res.status(200).send()` run. No line in the diff returns a failure status when `processEvent` throws.

Return a 5xx status from the `catch` block, so the provider retries the event.

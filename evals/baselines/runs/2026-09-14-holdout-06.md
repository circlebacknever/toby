## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from four banks, which are Chase, Monzo, Wise, and ING. Ledgerline matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. It writes the rows it cannot match to `review.csv` for a person to check. Ledgerline reads the accounting system through an API token with read-only scope.

#### Install

Ledgerline needs Python 3.11 or later. Install it with `brew install ledgerline`.

#### Add a bank format

To add a bank, write a parser at `parsers/<bank>.py`. A parser must not make network calls, and CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are in a single Redis node, which is at 71 percent of its memory and grows about 3 percentage points a week. At that rate, the node reaches 100 percent in about 10 weeks.

#### Option A: shard sessions across two Redis nodes

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, which took 2 ms at p95 in staging, but the team has not run sharded Redis before.

#### Option B: move sessions to Postgres

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres, which is 7 ms more than on Redis. The session read runs once per page load, so every page load makes one session read that is 7 ms slower at p95.

## 4

- **Consequence.** Every load of the admin dashboard reads all 1.2 million rows of the `users` table into the handler and then takes the array's length to get one number (admin/stats.ts:22).
- **Fires when.** An admin opens the admin dashboard, because this handler runs on every load of that page.
- **Guard.** The `findMany()` call at line 22 passes no arguments, so nothing in the query limits the rows it returns.

Fix direction is to have the database count the rows, so the query returns one number. I did not run the handler, so its response time and memory use with 1.2 million rows are unmeasured.

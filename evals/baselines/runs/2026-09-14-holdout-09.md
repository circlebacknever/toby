## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from Chase, Monzo, Wise, and ING. For each bank row, it searches for a ledger entry with the same amount and a date within 2 days. When it finds no match, Ledgerline writes the row to `review.csv` so a person can check it. It reads the accounting system with an API token that has read-only scope.

### Install

Ledgerline needs Python 3.11 or later. To install it, run `brew install ledgerline`.

### Adding a bank format

Each bank format is a parser in `parsers/<bank>.py`, so a new bank needs a new file there named after the bank. A parser must make no network calls, and CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are stored in a single Redis node that is at 71 percent of its memory. Usage grows about 3 percentage points a week, so at that rate the node reaches 100 percent in about 10 weeks.

#### Option A: shard sessions across two Redis nodes

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, where they took 2 ms at p95 in staging. The team has not run sharded Redis before.

#### Option B: move sessions to Postgres

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads on Postgres took 9 ms at p95, against 2 ms on Redis. The session read runs once per page load, so that 7 ms difference at p95 applies to every page load.

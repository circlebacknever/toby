## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from Chase, Monzo, Wise, and ING. Ledgerline matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. It writes each row it cannot match to `review.csv`, so a person can check that row. Ledgerline reads the accounting system through an API token with read-only scope.

#### Install

Ledgerline needs Python 3.11 or later. Install it with `brew install ledgerline`.

#### Add a bank format

Each bank format is a parser in `parsers/<bank>.py`, so a new bank needs a new parser at that path. Parsers must not make network calls, and CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are stored in a single Redis node, which is at 71 percent of its memory. Its memory use grows about 3 percentage points a week, so the node reaches full memory in about 10 weeks at that rate. The session read runs once per page load, so its latency is part of every page load.

#### Option A: Shard sessions across two Redis nodes

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, which took 2 ms at p95 in staging. The team has not run sharded Redis before.

#### Option B: Move sessions to Postgres

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres and 2 ms on Redis. Because the session read runs once per page load, Option B raises its staging p95 from 2 ms to 9 ms on every page load.

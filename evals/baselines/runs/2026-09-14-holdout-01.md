## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from Chase, Monzo, Wise, and ING. It matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. Ledgerline writes the rows it cannot match to `review.csv` for a person to check. It reads the accounting system through an API token with read-only scope.

#### Install

Ledgerline needs Python 3.11 or later. Install it with `brew install ledgerline`.

#### Add a bank format

Each bank format is a parser in `parsers/<bank>.py`, so you add a bank by writing a parser file there. A parser must not make network calls, and CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are stored in a single Redis node, which is at 71 percent of its memory. Its memory use grows about 3 percentage points a week, so at that rate the node is full in roughly 10 weeks.

#### Option A, a second Redis node

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, where they took 2 ms at p95 in staging, but the team has not run sharded Redis before.

#### Option B, the Postgres cluster

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres and 2 ms on Redis. The session read runs once per page load, so Option B makes that read 7 ms slower at p95 on every page load.

## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from Chase, Monzo, Wise, and ING. Ledgerline matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. It writes rows it cannot match to `review.csv` for a person to check. Ledgerline reads the accounting system through an API token with read-only scope.

#### Install

Ledgerline needs Python 3.11 or later. Install it with `brew install ledgerline`.

#### Adding a bank format

To add a bank, write a parser in `parsers/<bank>.py`. The parser must not make network calls, because CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are in a single Redis node, which is at 71 percent of its memory and grows about 3 percentage points a week. The session read runs once per page load.

#### Option A: Shard sessions across two Redis nodes

Add a second Redis node and shard sessions across both. Session reads stay on Redis, which took 2 ms at p95 in staging. The team has not run sharded Redis before.

#### Option B: Move sessions to Postgres

Move sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres and 2 ms on Redis. Because the session read runs once per page load, every page load would wait on the slower read.

## 4

### `admin/stats.ts:22` fetches every user row to count them

- **Consequence.** Every load of the admin dashboard fetches all 1.2 million rows of the `users` table and keeps them in memory only to read `.length` (admin/stats.ts:22).
- **Fires when.** An admin opens the admin dashboard, because this handler runs on every load.
- **Guard.** The call passes no arguments to `findMany()`, so nothing limits the rows it returns.

A count query, such as `db.users.count()` if the client provides it, returns the number without fetching the rows. This finding comes from reading line 22, and I did not run the handler.

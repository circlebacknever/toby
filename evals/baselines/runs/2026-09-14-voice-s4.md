## 1
The flaky test fails on CI because it asserts on a timestamp formatted in the machine's local timezone, and CI runs in UTC. It fails about one run in nine there and passed every run on my machine. I have not written the fix yet. The timezone difference explains why CI and local disagree, but it does not yet explain why only one CI run in nine fails. Next I will format the timestamp in UTC inside the test and run the CI job repeatedly until the failure rate is known.

## 2
A retry wrapper around the whole sync job will write duplicate rows. A partial run writes rows before it fails, and the retry writes those rows again. At two failures a week, that means two batches of duplicates to find and delete by hand. If each row has a stable source ID, switch the inserts to upserts keyed on that ID. After that change, the retry wrapper is safe to add. Until the upserts land, leave the job without a retry, because a failed run costs less to repair than a doubled one.

## 3
### Move rate-limit checks into one middleware

This PR moves the rate-limit checks out of four route handlers and into one middleware. It deletes the token-bucket code that each of the four handlers duplicated.

### Behavior change

The limit now applies per account across all routes. Before this PR, each route kept a separate limit for each account, so an account got the full allowance on every route. A client that spreads requests across several routes will now receive 429 responses sooner.

### Tests

This PR adds a test for the 429 path, which had no test before.

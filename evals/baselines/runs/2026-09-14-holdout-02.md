## 1

### Ledgerline

Ledgerline is a command-line tool that reconciles bank CSV exports against an accounting system. It reads exports from four banks, which are Chase, Monzo, Wise, and ING. Ledgerline matches a bank row to a ledger entry when the amounts are equal and the dates are within 2 days of each other. Rows it cannot match go to `review.csv` for a person to check. Ledgerline reads the accounting system through an API token with read-only scope.

#### Install

Install Ledgerline with `brew install ledgerline`. Ledgerline needs Python 3.11 or later.

#### Adding a bank format

Each bank format is a parser in `parsers/<bank>.py`, so add a bank by writing its parser at that path. A parser must not make network calls, so CI fails any parser that imports `requests` or `httpx`.

## 3

### Options considered

Sessions are in a single Redis node, which is at 71 percent of its memory and grows about 3 percentage points a week. If that rate holds, the node reaches full memory in about 10 weeks. Every page load runs one session read.

#### Option A, two sharded Redis nodes

Option A adds a second Redis node and shards sessions across both nodes. Session reads stay on Redis, where they took 2 ms at p95 in staging. The team has not run sharded Redis before.

#### Option B, sessions in Postgres

Option B moves sessions to the existing Postgres cluster, which has 40 percent headroom. In staging, session reads took 9 ms at p95 on Postgres and 2 ms on Redis. Because every page load runs one session read, Option B adds that 7 ms difference at p95 to each page load.

- **Consequence:** Every load of the admin dashboard fetches all 1.2 million rows of `users` to count them (admin/stats.ts:22). The handler builds one object per row and then reads only `.length`.
- **Fires when:** An admin opens the dashboard, because this handler runs on every load of that page.
- **Guard:** The `findMany()` call has no `select`, `where`, or `take`, so nothing limits the rows or columns it returns.
- **Fix:** If `db` is a Prisma client, `db.users.count()` returns the number from the database without fetching the rows.

This finding comes from reading the diff. I did not run the handler, so the load time is not measured.
